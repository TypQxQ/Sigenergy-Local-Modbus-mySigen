# Sigenergy ESS – mySigen cloud 0.1.1

Everything from the five 0.1.1 betas, as a stable release: a default install from the Marketplace gets it without enabling prereleases.

**Before installing.** Requires Home Assistant Core 2026.11.0 or later and Sigenergy Local Modbus 2.0.3 or later with a plant set up. This is an unofficial project that uses the mySigen app's private interface, which Sigenergy can change or close at any time. See the [guide](https://github.com/TypQxQ/Sigenergy-Local-Modbus-mySigen/blob/v.0.1.1/docs/USAGE.md) for every entity.

Existing connections keep their settings and entity IDs. New controls start disabled and need **Allow battery control**; like every change, they are checked first, sent once and only count when mySigen shows them.

## New since 0.1.0

- **Sigen AI strategy preference and vacation mode.** A dropdown for the app's AI Mode strategy preference (Profit Max, Balanced Energy or Self-use First) and a switch for its vacation mode. Both work only in Sigen AI mode and are unavailable in any other mode, Remote EMS included; neither changes the operating mode. Requested in Sigenergy-Local-Modbus discussion 385.
- **Smart loads.** An on/off switch for each smart load on the SigenStor's or the Gateway's own ports, named after the load in the app. It works while the load is under manual control in mySigen, also while Remote EMS is on. Requested in Sigenergy-Local-Modbus discussions 355, 99 and 334.
- **Storm Watch alert.** Where mySigen shows Storm Watch for the plant, a binary sensor is on while Storm Watch lists a weather alert that hasn't ended, with the weather, when charging starts and when the alert ends. Requested in Sigenergy-Local-Modbus discussion 243.
- **PV string names.** The names you give your PV strings in the app become the names of the PV string devices in Sigenergy ESS, and their entities follow. A device you renamed yourself is never changed, entity IDs stay the same, and removing the add-on gives the default names back. Requested in Sigenergy-Local-Modbus discussion 220.
- **Battery modules.** One device per module, under its inverter, with charge level, cell temperature and voltage, lifetime discharge, model, firmware and rated capacity.
- **Max grid connection current**, as in the app's *Grid Settings*, and **generator power per phase**.
- **Overrides from 1 minute to 24 hours**, as the app allows.
- **Entity name language** under Reconfigure: the same as Sigenergy ESS, Automatic, or one of eleven languages.
- **AC charger in the diagnostics.** No AC charger controls yet; the diagnostics read an AC charger's settings so one file from an owner is enough to build them.

## Fixed since 0.1.0

- **DC charger settings work while Remote EMS is on**, and the charge limit and V2X minimum are available on plants where mySigen gives no range.
- **Allow battery export to grid showed the opposite.** Check the switch once after updating if you used it.
- **Ready for newer Home Assistant:** probatio instead of voluptuous, and the device registry used the way Home Assistant 2027.9 requires. Every release is checked on Home Assistant 2026.10.0 and 2026.11.2.

## What has been tried on a real plant

Battery modules, smart loads, vacation mode and the strategy preference were tried on one European plant with a Gateway and no charger. Testers in Europe and Australia have since confirmed that **disconnecting from the grid** works (off and back on, two plants), and that **changing the DC charging mode** works on a real 25 kW charger; the V2X state also reads correctly. The DC charge limit and V2X minimum fix for plants without a range, and the V2X switch, are not confirmed yet. Storm Watch and PV string names are covered by tests only: no plant with Storm Watch, or with PV string names set, has been read yet. Have one of these? [Join the test](https://github.com/TypQxQ/Sigenergy-Local-Modbus-mySigen/discussions/38); even a diagnostics file helps.
