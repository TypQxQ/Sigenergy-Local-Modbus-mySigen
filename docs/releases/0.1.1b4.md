# Sigenergy ESS – mySigen cloud 0.1.1 Beta 4

**Before installing.** Requires Home Assistant Core 2026.11.0 or later and Sigenergy Local Modbus 2.0.3 or later with a plant set up. This is a beta: enable prereleases for this repository in the Marketplace to get it. See the [guide](https://github.com/TypQxQ/Sigenergy-Local-Modbus-mySigen/blob/v.0.1.1b4/docs/USAGE.md#-smart-loads) for the new switches.

- **Smart loads.** Each smart load on the SigenStor's or the Gateway's own ports gets an on/off switch, named after the load in the mySigen app. It needs **Allow battery control**, starts disabled, and works while the load is under manual control in mySigen. Remote EMS doesn't switch smart loads, so the switch also works while it is on. Like every other change, it is checked first, sent once and only counts when mySigen shows it. Power and energy of each smart load stay in Sigenergy ESS; loads on third-party devices are left out. Requested in Sigenergy-Local-Modbus discussions 355, 99 and 334.

Tried on one plant, with loads on both the SigenStor and the Gateway: switching on and off, and loads added or removed in the app. Have a smart load? Tell us how the switch works for you in [discussion 20](https://github.com/TypQxQ/Sigenergy-Local-Modbus-mySigen/discussions/20); the diagnostics now list each load's port, device and state, without the names.

- **AC charger in the diagnostics.** No AC charger controls yet: mySigen has two ways of storing the charging mode, and which one a charger uses is unknown. When mySigen lists an AC charger, the diagnostics now read it once: its supported charging modes, the charging mode settings and the live session values, with everything but codes and settings masked. Have a Sigen EVAC? A diagnostics file in [discussion 20](https://github.com/TypQxQ/Sigenergy-Local-Modbus-mySigen/discussions/20) is all it takes to get the controls built.

Existing connections keep their settings and entity IDs. Everything from 0.1.1 Beta 1 to Beta 3 is included.
