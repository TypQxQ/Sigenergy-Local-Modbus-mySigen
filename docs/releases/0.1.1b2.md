# Sigenergy ESS – mySigen cloud 0.1.1 Beta 2

**Before installing.** Requires Home Assistant Core 2026.11.0 or later and Sigenergy Local Modbus 2.0.3 or later with a plant set up. This is a beta: enable prereleases for this repository in the Marketplace to get it. See the [guide](https://github.com/TypQxQ/Sigenergy-Local-Modbus-mySigen/blob/v.0.1.1b2/docs/USAGE.md) for every entity.

- **Overrides from 1 minute to 24 hours.** The mySigen app allows a custom override of 1 to 1440 minutes, and so does the add-on now, for the Next override duration and the `start_battery_override` action. It was 30 to 120 minutes.
- **Max grid connection current**, a new plant setting while battery control is allowed: the most current per phase the plant draws from the grid, as in the app's *Grid Settings*. It shows unknown while no limit is set; setting it also switches the limit on (switch it off in the app), and it can't go above the installer's limit. It starts disabled. The same rules as every change apply: read first, sent once, confirmed by reading back.
- **Generator power per phase**, three new sensors next to the generator's voltage and current per phase. Like the other generator sensors, they start disabled.
- **Entity name language** under Reconfigure, as in Sigenergy ESS: *Same as Sigenergy ESS* (the default, as before), *Automatic* for the Home Assistant server language, or one of the eleven languages. Entity IDs and names you set yourself are kept.
- **Ready for newer Home Assistant.** Forms and actions now use probatio, the validation library Home Assistant 2026.10 and later is built on, instead of voluptuous, which Home Assistant no longer requires. Removing the add-on also uses the device registry the way Home Assistant 2027.9 will require. Every release is now checked on Home Assistant 2026.10.0 and 2026.11.2.

Also in this beta, from 0.1.1 Beta 1: one device per battery module with its charge level, cell temperature and voltage, and lifetime discharge, listed with the other Sigenergy ESS devices.

Existing connections keep their settings and entity IDs. Ideas came from comparing with [sigenergy2mqtt](https://github.com/seud0nym/sigenergy2mqtt). [Join the test](https://github.com/TypQxQ/Sigenergy-Local-Modbus-mySigen/discussions/20); even a diagnostics file helps.
