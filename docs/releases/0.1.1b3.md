# Sigenergy ESS – mySigen cloud 0.1.1 Beta 3

**Before installing.** Requires Home Assistant Core 2026.11.0 or later and Sigenergy Local Modbus 2.0.3 or later with a plant set up. This is a beta: enable prereleases for this repository in the Marketplace to get it. See the [guide](https://github.com/TypQxQ/Sigenergy-Local-Modbus-mySigen/blob/v.0.1.1b3/docs/USAGE.md#-dc-charger) for the DC charger controls.

Fixes from the first reports with a DC charger, in [discussion 20](https://github.com/TypQxQ/Sigenergy-Local-Modbus-mySigen/discussions/20):

- **DC charger settings work while Remote EMS is on.** The charging mode, charge limit, minimum EV charge for V2X and Allow power from EV were refused in Remote EMS. That rule was wrong: these settings exist only in mySigen, Remote EMS and Modbus don't control them, and the mySigen app doesn't block them either. Battery overrides and the operating mode are still refused in Remote EMS, as they do conflict with it.
- **DC charge limit and Minimum EV charge for V2X are available on more plants.** They stayed unavailable where mySigen gave no allowed charge level range. Like the mySigen app, the add-on now takes a missing limit as 0 to 100 % for the charge limit, and uses the charger's own limits for the V2X minimum (20 to 100 % when not given).
- **Allow battery export to grid showed the opposite.** mySigen stores this setting as a *limitation* (on means blocked), and the switch showed that value as "allowed". It now shows on when the battery may export, and turning it on or off sends the matching value; the `in_effect` attribute is corrected the same way. Nothing in mySigen was changed by this fix: check the switch once after updating if you used it.

Existing connections keep their settings and entity IDs. Everything from 0.1.1 Beta 1 and Beta 2 is included: battery module devices, overrides from 1 minute to 24 hours, max grid connection current, generator power per phase and the entity name language.
